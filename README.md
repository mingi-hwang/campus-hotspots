### 페이지별 스타일
- 프론트페이지: 첫페이지의 친근함을 주기위해 분홍색을 사용했다 / body에 page-home class를 적용했다. css는 분홍색 계열을 사용하고 Trebuchet MS 글꼴을 사용했다.
- 식당: 시원한 느낌을 주기위해 파란색을 사용했다. / body에 page-foodcourt class를 적용했다. css는 파란색 계열을 사용하고 Jua 글꼴을 사용했다.
- 카페: 햇살같이 따뜻한 느낌을 주고 싶어 주황색을 사용했다. / body에 page-cafe class를 적용했다. css는 주황색 계열을 사용하고 Georgia 글꼴을 사용했다.
- 편의점: 풀처럼 자연의 향을 추구하기 위해 초록색을 사용했다. / body에 page-shelter class를 적용했다. css는 초록색 계열을 사용하고 Gowun Dodum 글꼴을 사용했다.

### 모바일 스타일
- 적용한 @media 조건: @media (max-width: 600px)
- 모바일에서 특별히 바뀌는 부분과 이유: 페이지의 너비를 94%로 줄여 화면 양쪽에 여백을 만들었다. 페이지와 패널의 여백과 padding을 줄여 작은 화면에서도 내용이 잘 보이도록 했다. 제목 크기를 2rem으로 줄여 긴 제목이 화면 밖으로 나가지 않도록 했다. 하단 페이지 이동 메뉴를 세로 방향으로 배치해 링크가 겹치지 않도록 했다. 이미지가 화면 너비를 넘지 않도록 max-width: 100%를 적용했다.
- 휴대전화에서 네 페이지를 확인한 결과: 가시성이 잘보이게 적용이 되었고 여백도 적절하게 들어가서 글자들의 배치가 괜찮게 보였다.

## 5주차 · 나만의 취향 밸런스 게임

- 게임 주소: https://mingi-hwang.github.io/campus-hotspots/week5/
- 게임 이름과 소개: 학점 예측 게임, 질문을 통해서 자신의 학점을 예측을 한다.
- 게임의 대상과 주제를 선택한 이유: 질문의 답이 명확하기도 하고 한 행동을 통해 학점을 예측하는 것이 재밌어보였기 때문
- 기본 예제에 없는 질문 최소 4개: 출석 한번도 안빼먹고 강의를 다녔는가? , 교수님의 강의를 듣는 방식은? , 과제를 받았을 때는? , 시험기간에는? , 팀플 기간에는? , 수업이 다 끝나고 집(기숙사)에서는?
- 직접 만든 결과 이름·설명과 선택의 연결: A0A+: 성실하게 공부하는 당신. 당신의 노력이 학점을 만들어줍니다. B0B+: 힘들어도 열심히 한 당신. 좀 더 노력하면 A를 향해갈 수 있습니다. C0C+: 아쉬운 결과지만, 다음을 위해 노력해보세요. D0D+: 자신의 과거를 돌아보며 성찰을 해봐야 할 것 같아요. F: 학교 다니기 싫으신가요?...
- 나만의 표현 한 가지와 구현한 위치: 결과 종류를 늘렸음
- 결과 분류 규칙과 동점 처리: 6점은 A 4,5점은 B 2,3점은 C 1점은 D 0점은 F로 분류

### 저장 설계
- sessionStorage에 저장한 값과 이유: 현재 진행 중인 질문 번호, 별명, 각 질문의 선택 내용 등을 저장했음, 질문을 끝마치지 못한 상태에서 새로고침해도 이어서 답할 수 있도록 하기 위해서
- localStorage에 저장한 값과 이유: 모든 질문에 답한 뒤의 별명, 선택 결과, 예상 학점, 완료 시간 등을 저장했음, 브라우저를 다시 방문해도 완료한 결과를 확인하고 친구의 결과와 비교할 수 있도록 하기 위해서
- 내 데이터 조회·개별 삭제·전체 삭제 동작: 내 저장 데이터 보기를 누르면 진행 중인 답변과 완료 기록을 확인할 수 있다. 각 기록 옆의 이 기록 삭제 버튼으로 개별 기록을 삭제할 수 있으며, 진행 중인 답변 삭제 버튼으로 임시 답변을 삭제할 수 있다. 게임 데이터 전체 삭제 버튼을 누르면 sessionStorage와 localStorage에 저장된 모든 게임 데이터를 삭제한다.

### 확인 결과
- 브라우저와 실험 조건: 엣지에서 실험하였음
- 새로고침 / 독립적인 새 탭 / 탭 닫기 비교: sessionstorage는 새로고침을 해도 유지되지만 탭을 닫고 새로 열게 되면 사라짐 다만 localstorage는 사라지지 않음
- 중복 저장 / 잘못된 데이터 / 삭제 후 재방문 확인: 중복 저장은 안되며 잘못된 데이터는 제외가 되었고 삭제 후 재방문을 하니 삭제된 데이터는 안보였음
- 브라우저 저장값을 신뢰할 수 없는 이유: 사용자가 개발자 도구로 저장값을 직접 변경할 수 있고, 저장 공간 부족이나 브라우저의 저장 기능 차단으로 저장에 실패할 수도 있기 때문
- 적용한 방어 방법: 저장값을 JSON으로 변환하고, 읽을 때 자료형·질문 ID·선택값·질문 버전·완료 시간 등을 검사했다. 잘못된 데이터는 제외하거나 삭제한다. 완료 기록은 최대 20개까지만 유지하도록 했음
